# Reglas de validación

## Validaciones estructurales

1. El documento contiene exactamente trece secciones principales.
2. Las secciones mantienen el orden canónico.
3. La numeración no presenta saltos ni duplicados.
4. Cada hito utiliza la misma estructura interna.
5. Las secciones 11, 12 y 13 conservan el texto aprobado de la plantilla.
6. No se crean capítulos ERP, técnicos o anexos sin autorización.

## Validaciones de información

1. No se inventan nombres, fechas, responsables, sistemas ni campos.
2. Un dato faltante se registra como `[PENDIENTE POR DEFINIR]`.
3. Los nombres suministrados se mantienen sin sustituciones.
4. Las afirmaciones relevantes conservan referencia a su evidencia.
5. Una contradicción se reporta y no se resuelve automáticamente.

## Objetivos

- Inician con verbo en infinitivo.
- Expresan resultados.
- No describen actividades como si fueran resultados.

## Historias de usuario

- Utilizan Como / Quiero / Para.
- Contienen un actor, una necesidad y un beneficio.
- No agrupan funcionalidades independientes.

## Criterios de aceptación

- Son verificables.
- Evitan términos ambiguos.
- Definen resultado, condición o restricción.
- No utilizan “rápido”, “fácil” o “varios” sin métrica o explicación.

## Requerimientos

- Utilizan “El sistema deberá...” cuando se redactan como requisito.
- Expresan una sola necesidad principal.
- No mezclan fases futuras con el alcance actual.
- Mantienen trazabilidad hacia fuentes y decisiones.

## Aprobación

- La IA nunca establece el estado APROBADO.
- Solo un usuario autorizado aprueba.
- La aprobación registra persona, cargo, fecha y estado.
- Un documento aprobado no se modifica; se crea una nueva versión.
